# 글자·간격 규칙

이 사이트의 글자 크기, 행간, 회색 글자, 간격을 정한 규칙이다. CSS를 고치기 전에 읽고,
고친 뒤에는 `node tools/ui_check.cjs`로 벗어난 곳이 0곳인지 확인한다.
(2026-11-20에 정했다. 왜 이렇게 정했는지는 DECISIONS.md 21번.)

화면은 두 종류이고, 쓰임이 달라서 글자 크기 단계를 따로 둔다.

- **도구 화면**: 이미지 도구(`template.html`), 영상 도구(`template-video.html`),
  Chrome 확장(같은 `template.html`로 만든다, `extension/src/ext.css`). 단추와 라벨이 많은 작업 화면이다.
- **읽기 페이지**: About·사용법·활용 예시·개인정보 처리방침(`template-page.html`). 긴 글을 읽는 화면이다.

세 언어(en·ko·ja)가 같은 단계를 쓴다. 언어마다 다른 크기를 두지 않는다.

## 1. 글자 크기: 다섯 단계

CSS에는 숫자를 쓰지 않고 변수 `var(--fs-1)` … `var(--fs-5)`만 쓴다.

| 단계 | 도구 화면 | 읽기 페이지 | 쓰는 자리 |
|---|---|---|---|
| `--fs-1` | 24px | 30px | 도구: 로고, 놓기 영역 제목, 내보내기 진행 숫자 · 읽기: 페이지 제목(h1) |
| `--fs-2` | 18px | 22px | 도구: 파일 이름, 로그인 창 제목, 다른 도구 배너 제목, 닫기·더하기 아이콘 · 읽기: 절 제목(h2) |
| `--fs-3` | 14px | 17px | 본문. 도구: 질문, 둘러보기 설명, 로그인 안내, 푸터 제목 · 읽기: 본문, 머리글(lead), 소제목(h3), 질문 |
| `--fs-4` | 13px | 15px | 도구: 단추·입력칸·비율 단추, 도움말(hint), 경고·완료 문구, 머리 설명(tagline), 푸터 · 읽기: 표, 코드, 키 |
| `--fs-5` | 12px | 13px | 작은 글. 도구: 칸 머리 라벨(대문자), 크기·위치 숫자 줄, 상자 번호표, 썸네일 표, 보조 정보 · 읽기: 언어 전환, 도구 열기 단추, 푸터 |

- **12px보다 작은 글자는 없다.** 예전에 9·10·11px이던 썸네일 표, 대문자 라벨, 단축키 표시는 모두 12px이 되었다.
- 로고는 읽기 페이지에서도 도구와 같은 24px(`--fs-logo`)이다. 단계 밖의 값은 이것 하나다.
- 휴대폰에서 낮추는 단계는 없다. 320px 화면에서도 가장 긴 제목이 줄바꿈으로 들어간다.
  나중에 넘치는 제목이 생기면 그 제목만 한 단계 낮춘다(새 크기를 만들지 않는다).
- `/stats` 관리자 화면(`src/stats.js`)은 아직 이 규칙 밖이다. 데이터가 있어야 화면을 확인할 수 있어서 이번에는 다루지 않았다.

## 2. 행간: 두 가지

| 변수 | 값 | 쓰는 자리 |
|---|---|---|
| `--lh-1` | 1.4 | 한 줄짜리: 제목, 라벨, 단추, 숫자. 도구 화면 `body`의 기본값 |
| `--lh-2` | 1.7 | 줄이 바뀌는 글: 도움말, 머리 설명, 안내문, 둘러보기, 푸터, 배너 설명. 읽기 페이지 `body`의 기본값 |

도구 화면에서 여러 줄이 될 수 있는 글을 새로 만들면 `line-height:var(--lh-2)`를 붙인다.
`body`는 1.4라서 붙이지 않으면 줄이 빽빽해진다.

`line-height:1`과 `0`은 글이 아닌 것에만 쓴다. 아이콘 글자(×, +, 화살표), 높이가 정해진 번호표,
이미지를 담는 상자가 여기에 해당한다. **`line-height:0`인 상자 안에 글을 넣으면 그 글에
`--lh-1`을 꼭 준다.** 썸네일의 '예시' 표가 이 상자 안에 있다.

## 3. 회색 글자

색은 두 가지를 구분한다.

- `--ink-2`(#a8c3ca, 밝은 회청색): 보조 글. 크기 제한이 없다. 단추 글, 머리 설명, 파일 크기 같은 값.
- `--muted`(#7d97a1): **회색 글자**. 아래 자리에서만, `--fs-4`·`--fs-5`에서만 쓴다.
  - 라벨: 칸 머리, 입력칸 이름, 대문자 소제목
  - 단위·구분 기호: px, ×, 위치·크기 줄의 이름 부분
  - 각주: 컨트롤 아래 도움말(hint), 로그인 창 작은 글, 푸터
  - 빈 화면 안내, 불러오는 중 표시
  - 손대지 않은 상태: 0인 기울기 값처럼 '아직 안 건드림'을 회색으로 보여 주는 곳

  쓰지 않는 자리: **숫자 값, 본문, 링크, 단추 글**. 숫자 값은 `--ink-2`나 강조색을 쓴다.
- `--muted`는 어두운 판(`--panel-2` #162a34) 위에서도 4.8:1 대비가 되도록 #6d8b96에서 #7d97a1로 밝혔다.
  더 어둡게 내리지 않는다(4.5:1 아래로 떨어진다).

## 4. 간격: 4px의 배수

`margin`, `padding`, `gap`의 px 값은 전부 **4의 배수**다(0, 4, 8, 12, 16, 20, 24, 32, 40, 44, 48 …).
단추·칩 높이도 4의 배수로 둔다(32, 44).

- 2px, 6px처럼 애매한 값이 필요해 보이면 더 작은 쪽(4)이나 큰 쪽(8) 중 하나를 고른다.
- 선 굵기(`border`, `outline`), 위치값(`top`, `left`, `inset`), 크기(`width`, `height`의 작은 장식)는 이 규칙 밖이다.
- 어쩔 수 없이 벗어나는 값은 같은 줄에 이유를 적는다: `/* ui-ok: <이유> */`.
  지금은 두 곳이다. 기울기 막대의 2px 선과 20px 손잡이를 가운데에 맞추는 `margin-top:-1px`, `-9px`.

## 5. 점검

```bash
node tools/ui_check.cjs     # 벗어난 곳을 줄 번호와 함께 보여 주고, 있으면 1로 끝난다
```

세 템플릿의 `<style>`과 `style="…"`, `extension/src/ext.css`를 읽고 다음을 센다.

1. `font-size`가 `--fs-1`…`--fs-5`(읽기 페이지는 `--fs-logo`도) 또는 `inherit`인가
2. `line-height`가 `--lh-1`·`--lh-2`인가(1과 0은 위 2절의 경우만)
3. `margin`·`padding`·`gap`의 px 값이 4의 배수인가
4. `color:var(--muted)`인 규칙의 글자 크기가 `--fs-4`·`--fs-5`인가, 링크가 아닌가

글자 크기를 바꾸면 화면도 띄워 본다. PC 1440, 휴대폰 390·320, 세 언어에서 가로 넘침과 잘림(…)이 없는지 본다.
`overflow:hidden`과 `text-overflow:ellipsis`를 같이 쓰는 칸(기울기 라벨, 프리셋 이름 등)은
글자가 커지면 잘리기 시작한다.

## 6. 이 규칙 밖의 것

- 캔버스에 그리는 글자(내보낸 이미지 안의 번호 등)는 CSS가 아니다.
- 글의 양은 다루지 않는다. 문구를 줄이는 일은 따로 한다.
- 사용법 페이지의 단계 그림(`public/img/how-to/`)은 예전 화면이다. 글자 크기가 조금 달라졌을 뿐
  배치는 같아서 다시 찍지 않았다. 도구 화면 배치를 바꿀 때 함께 다시 찍는다(DECISIONS.md 13번).
